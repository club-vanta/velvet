# Paid Entrance Tracking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the backend's paid-entrance tracking in the frontend, so org admins can mark payments and staff at the door are blocked from checking in guests who have not paid.

**Architecture:** Additive changes to three existing pages (`MeetupsPage`, `MeetupDetailPage`, `EventsPage`) plus two new shared components (a `Checkbox` primitive and a `ReasonDialog`). All payment state comes from fields the backend already returns on existing endpoints, so there are no new queries — only new mutations and new conditional rendering. Every payment mutation is gated behind the existing `isOrgAdmin` check.

**Tech Stack:** React 19, TypeScript, Vite, TanStack Query v5, `openapi-fetch` with types generated from the backend's OpenAPI schema, shadcn/ui v4 (`base-nova` style) built on Base UI, Tailwind v4, Vitest + Testing Library, sonner for toasts.

**Spec:** `docs/superpowers/specs/2026-08-06-paid-entrance-tracking-design.md`

## Global Constraints

- **Never hand-edit `src/api/types.ts`.** It is generated by `npm run generate:api`.
- **Primitives are Base UI, not Radix.** Import from `@base-ui/react/*`. Snippets from Radix-era shadcn docs will not compile.
- **Every user-facing string goes through `useLanguage()`.** Add the key to **both** the `en` and `es` blocks of `src/lib/i18n.tsx`. `TranslationKey` is `keyof typeof translations.en` and `t()` indexes `translations[lang]`, so a key missing from `es` is a type error.
- **`t()` takes a key and nothing else — there is no interpolation.** Compose dynamic text in JSX, e.g. `{t("undoDialogTitle")} {guest.displayname}?`.
- **`formatDateTime(iso: string)` does not accept `null`.** Guard nullable timestamps: `x ? formatDateTime(x) : ""`.
- **Admin gate is `const isOrgAdmin = isSiteAdmin || activeOrg?.role === "ADMIN"`**, where `isSiteAdmin = user?.role.name === "SITE_ADMIN"`. Copy this from `GuestsPage.tsx:663-664`.
- **Mutation error handling:** always `throw new Error(extractApiError(error, "<fallback>"))` in `mutationFn`, and `onError: (err: Error) => toast.error(err.message)`.
- **Spanish copy:** the app uses club slang for some terms (`banned` → "Vanteado", `walk-in` → "Discreto"). Payment terms have no slang; use plain Spanish exactly as given in this plan.
- **Commit hooks run `tsc --noEmit`, Prettier, and ESLint.** A commit fails if any of them fail. Run `npx prettier --write <files>` before committing if the format check trips.
- **Do not add a payment filter to the guest table.** A generic column-filter system is deliberately deferred to its own spec.

```tsx
import { useState } from "react";
import { Button } from "@/components/ui/button";
import { Textarea } from "@/components/ui/textarea";
import {
  Dialog,
  DialogContent,
  DialogHeader,
  DialogTitle,
  DialogFooter,
} from "@/components/ui/dialog";
import { useLanguage } from "@/lib/i18n";

const MIN_REASON = 5;
const MAX_REASON = 500;

type ReasonDialogProps = {
  title: React.ReactNode;
  placeholder: string;
  confirmLabel: string;
  pendingLabel: string;
  isPending: boolean;
  onConfirm: (reason: string) => void;
  onClose: () => void;
};

export function ReasonDialog({
  title,
  placeholder,
  confirmLabel,
  pendingLabel,
  isPending,
  onConfirm,
  onClose,
}: ReasonDialogProps) {
  const { t } = useLanguage();
  const [reason, setReason] = useState("");
  const trimmed = reason.trim();
  const isValid = trimmed.length >= MIN_REASON && trimmed.length <= MAX_REASON;

  return (
    <Dialog open onOpenChange={(o) => !o && onClose()}>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>{title}</DialogTitle>
        </DialogHeader>
        <div className="space-y-2 py-2">
          <label htmlFor="reason-dialog-reason" className="text-sm font-medium">
            {t("reasonRequired")}
          </label>
          <Textarea
            id="reason-dialog-reason"
            placeholder={placeholder}
            value={reason}
            onChange={(e) => setReason(e.target.value)}
            rows={3}
          />
          <p className="text-xs text-muted-foreground">
            {trimmed.length}/{MAX_REASON}
          </p>
        </div>
        <DialogFooter>
          <Button variant="ghost" onClick={onClose}>
            {t("cancel")}
          </Button>
          <Button
            variant="destructive"
            onClick={() => onConfirm(trimmed)}
            disabled={!isValid || isPending}
          >
            {isPending ? pendingLabel : confirmLabel}
          </Button>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  );
}
```

function UndoDialog({
  guest,

  meetupId,
  onClose,

  guest: MeetupGuest;
  orgId: string;
  meetupId: string;
  onClose: () => void;

```tsx
function PaymentRequirementDialog({
  orgId,
  meetupId,
  enabling,
  onClose,
}: {
  orgId: string;
  meetupId: string;
  enabling: boolean;
  onClose: () => void;
}) {
  const { t } = useLanguage();
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: async () => {
      const path = enabling
        ? ("/organizations/{org_id}/meetups/{meetup_id}/enable-payment" as const)
        : ("/organizations/{org_id}/meetups/{meetup_id}/disable-payment" as const);
      const { data, error } = await api.PATCH(path, {
        params: { path: { org_id: orgId, meetup_id: meetupId } },
      });
      if (error)
        throw new Error(
          extractApiError(error, "Failed to update payment requirement"),
        );
      return data;
    },
    onSuccess: () => {
      void queryClient.invalidateQueries({
        queryKey: ["meetup", orgId, meetupId],
      });
      void queryClient.invalidateQueries({ queryKey: ["meetups", orgId] });
      toast.success(t("paymentRequirementUpdated"));
      onClose();
    },
    onError: (err: Error) => toast.error(err.message),
  });

  return (
    <Dialog open onOpenChange={(o) => !o && onClose()}>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>
            {enabling
              ? t("enablePaymentDialogTitle")
              : t("disablePaymentDialogTitle")}
          </DialogTitle>
        </DialogHeader>
        <p className="text-sm text-muted-foreground py-2">
          {enabling
            ? t("enablePaymentDialogBody")
            : t("disablePaymentDialogBody")}
        </p>
        <DialogFooter>
          <Button variant="ghost" onClick={onClose}>
            {t("cancel")}
          </Button>
          <Button
            onClick={() => mutation.mutate()}
            disabled={mutation.isPending}
          >
            {enabling ? t("enablePayment") : t("disablePayment")}
          </Button>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  );
}
```

The two `as const` assertions are needed so `openapi-fetch` narrows the path to a known literal rather than a widened `string`.

Both `["meetup", ...]` and `["meetups", ...]` are invalidated because the meetups list shows the "Paid event" badge added in Task 4.
